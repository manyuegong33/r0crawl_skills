# 通用方法论：多级 SMC + 反调试 + Feistel + 大域多项式求根类 CrackMe

> 适用题型：程序用多级自修改代码（SMC）层层解密，软断点会破坏密钥流；含动态反调试环境检测；核心是 Feistel 混淆器（可逆性分析）+ 大有限域（如 GF(2^127-39)）上的多项式求根。典型特征：导入表极少（Direct Syscall）、有 VirtualProtect/FlushInstructionCache、自定义 section（如 .tgt）存偏移/长度参数。

## 一、题型识别特征

- 导入表只有几个 KERNEL32 基础 API，无 I/O（Direct Syscall）。
- 有 VirtualProtect、FlushInstructionCache → 典型 SMC。
- 自定义 section（如 .tgt）内含多组 (偏移, 长度) 参数，指向待解密区域。
- 多级解密：Stage1 简单 XOR，Stage2 用 Stage1 明文算 Hash（FNV-1a 双种子）再经 fmix64 生成密钥流。
- 级联校验：软断点（0xCC）会改变 Stage2 密钥流 → 后续解密失败。
- 核心算法：Base-94 编码 → 128-bit 整数 → mod 多项式 P1；两个 Feistel 混淆器各 20 轮；反调试累加器。
- 最终在 GF(2^127-39) 等大域上求多项式根。

## 二、通用推导流程（6 步）

### 第 1 步：静态侦察与 SMC 还原
- 看导入表与节区特征，确认 SMC（VirtualProtect + FlushInstructionCache + 自定义 section）。
- 提取 .tgt 节内的 (偏移, 长度) 参数组。
- 写静态解密脚本（pefile + capstone）：Stage1 按简单规则（如 XOR 0x5A）解密；Stage2 先对 Stage1 明文算 Hash（FNV-1a 双种子 0xcbf29ce484222325 / 0x9e3779b97f4a7c15），再 fmix64 生成密钥流异或解密。
- 关键：全程静态解密，不打断点（避免 0xCC 污染密钥流）。

### 第 2 步：动态反调试环境过检
- 列出所有反调试点（PEB、NtQueryInformationProcess、硬件断点、时间戳）。
- 用 Unicorn/Qiling 仿真或 ScyllaHide 类插件过检，不在真实调试器下打断点。
- 反调试累加器：确认哪些检测结果会累加进密钥/状态，必须全部走"未检测到"分支。

### 第 3 步：外层编码还原（Base-94 → 大整数）
- 确认自定义 Base-N（如 Base-94）字符表与编码方向。
- 解码成字节后按大端/小端解释为大整数（如 128-bit）。

### 第 4 步：Feistel 混淆器可逆性分析
- 确认 Feistel 结构：轮数（如 20）、轮函数 F、子密钥来源。
- Feistel 天然可逆：逆推时交换左右半、逆序子密钥、F 不用逆（Feistel 性质）。
- 两个混淆器串联时，逆推顺序相反。

### 第 5 步：大域多项式求根
- 确认域（如 GF(2^127-39)，注意是素数域还是扩域）。
- 把目标多项式 P1 在该域上因式分解/求根（用 SageMath/Magma/pari-gp）。
- 根即中间态，可能需枚举多个根逐一验证。

### 第 6 步：拼接验证
- 根 → 逆 Feistel → 逆 Base-N → 候选输入。
- 在原始程序（无调试器、无断点）下验证。

## 三、验证清单

- [ ] 所有 SMC 层都静态解密，未用软断点。
- [ ] 反调试点全部列出并走"未检测到"分支。
- [ ] Base-N 字符表与字节序确认。
- [ ] Feistel 逆推在单块已知样本上自洽。
- [ ] 大域求根用专业工具（Sage/Magma/pari），根的数量与次数一致。
- [ ] 候选输入在原程序验证通过。

## 四、常见坑

| 坑 | 表现 | 规避 |
|---|---|---|
| 软断点污染密钥流 | Stage2 解密后乱码 | 全程静态解密或硬件断点 |
| FNV 种子用错 | 密钥流不对 | 从二进制直接提取双种子 |
| Feistel 想逆 F | 逆推卡死 | 利用 Feistel 性质：F 不用逆，交换+逆序子密钥即可 |
| 大域当素数域 | 求根失败 | 确认域特征（2^127-39 是素数，用 GF(p)） |
| 反调试累加器漏检 | 走到假分支 | 列出所有检测点，确认累加器初值 |
| 多个根没逐一验证 | 选错根 | 枚举所有根，每个都逆推验证 |
