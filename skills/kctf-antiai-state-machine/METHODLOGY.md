# 通用方法论：反AI/反自动化状态机类 CrackMe

> 适用题型：程序通过大量"诊断记录/状态字/error bitmap"间接反馈对错，不直接比较输入；含反调试、完整性校验、VM worker、ARX 置换等。典型特征：输入长度固定、输出只有 ok/no、内部维护多份状态记录。

## 一、题型识别特征

看到以下任意 3 条，基本可判定为本类：

- 输入定长（如 26 字节），程序读入后 strip CR/LF。
- 验证函数返回前把"长度差"写入某个全局差异量，而不是直接 return 0/1。
- 存在多份 diagnostic record（每个 worker 十几个 DWORD：末态 r/s、code key、VM PC、输出字节数、指令数、error bitmap、混合后的输出）。
- error 字段是多个子条件的 OR（duplicate_primary | complement(used_primary) | r_final^r_ref | s_final^s_ref | reduce_or(post^ref_post)）。
- 外层函数看到 error!=0 不立即返回，而是继续参与汇总运算（防止时序侧信道）。
- 有调试状态探测、.text 完整性计算，正常环境走未触发分支。

## 二、通用推导流程（5 步）

### 第 1 步：固定可观测事实
- 列出所有关键地址：调试探测、完整性计算、汇总函数、置换函数、总验证函数、单个 worker。
- 在正常桌面环境（无调试器、白名单父进程）跑多组样本，用 Unicorn/原生进程/低级指令模型三方对比，确认每份 worker 记录和汇总值完全一致。
- 目的：排除仿真误差，得到"可信任的整数模型"，后续求解用模型、验证用原程序。

### 第 2 步：还原内部状态的来源
- 找到"输入 → 内部状态"的构造点（如 26 字节拼 6 字节固定后缀成 32 字节，按小端解释为 8 个 DWORD）。
- 识别初始加白（whitening）：`A[i] ^= CONST - i*CONST2 (mod 2^32)`。
- 识别轮函数：每轮先更新两个位置（一个加法、一个 XOR+ROL），再调用固定的 ARX 置换。
- 关键：所有算子都必须可逆（加↔减、ROL↔ROR、XOR 自逆、置换可回代）。

### 第 3 步：建立合法状态的约束
- 逆回初始数组后，合法状态必须满足某些固定位（如 A[7]=0xC3D2E1F0、A[6]&0xFFFF0000==0xA55A0000）。
- 这些固定位用于淘汰"无法来自合法输入"的候选状态，把搜索空间从 2^256 压到可枚举。

### 第 4 步：理解 diagnostic record 的真实语义
- 把每个 worker 写出的字段逐个对应到内部变量（末态 r/s、code key、PC、输出长度、指令数、error、混合输出）。
- 推出 error 的精确计算式（哪些子条件 OR 而成）。
- 注意：VM 内部停止标志只负责离开循环，与 error 字段分开保存；外层不短路。

### 第 5 步：求解 + 原程序确认
- 用抽出的整数模型（SMT/暴力/逆推）求候选输入。
- 候选必须交还原程序确认（因为模型可能漏掉某些隐式约束）。

## 三、验证清单

- [ ] 三方（Unicorn/原生/指令模型）对同一输入产出完全相同的 worker 记录。
- [ ] 逆推回初始数组后，固定位约束全部满足。
- [ ] error 字段的每个子条件都能独立解释来源。
- [ ] 候选输入在原程序（未 patch、无调试器、白名单父进程）下跑出 ok。

## 四、常见坑

| 坑 | 表现 | 规避 |
|---|---|---|
| 把 error!=0 当成立即返回 | 时序分析出错 | 读汇总函数，确认 error 继续参与运算 |
| 忽略长度差写入全局 | 长度约束漏掉 | 检查验证函数返回前的所有写操作 |
| 仿真与原生不一致 | 求解基于错误模型 | 三方对比，固定可观测事实 |
| 固定位约束漏掉 | 搜索空间爆炸 | 逆推到初始数组后列出所有等式/掩码约束 |
| 反调试分支污染 | 走到假路径 | 在白名单父进程+无调试器下采样 |
