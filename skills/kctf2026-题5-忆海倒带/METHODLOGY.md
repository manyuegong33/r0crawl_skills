# 通用方法论：多层校验链 Windows CrackMe（XOR/校验和/RSA 部分覆盖/查表）

> 适用题型：单一输入（如 88 hex → 44 字节）经过多层独立校验（异或值、校验和、RSA 签名、查表），各层覆盖输入的不同区段。典型特征：每层校验常量可验证、RSA 只覆盖部分字节、可分段逆推。

## 一、题型识别特征

- 输入是定长 hex 串（如 88 hex = 44 字节）。
- 存在多层校验，每层一个可验证常量：
  - 某段 XOR 结果 == 常量（如 0x8F）
  - 某段校验和 == 常量（如 0xBEFF）
  - RSA 签名验证，但只覆盖输入的一部分（如 ArgList[28..43] 仅 16 字节）
  - 查表（lookup table）变换
- 各层覆盖区段不同 → 可分段独立逆推，再拼接。

## 二、通用推导流程（5 步）

### 第 1 步：画出"校验层 × 输入区段"覆盖图
- 列出所有校验层及其作用的字节范围。
- 标注每层的验证常量（XOR 值、校验和、RSA 模数/指数、表地址）。
- 关键发现：RSA 只覆盖部分字节 → 其余字节可由其它层独立确定。

### 第 2 步：分段逆推非 RSA 区段
- XOR 层：目标字节 = 常量 XOR 已知字节。
- 校验和层：枚举/逆推使累加和等于常量。
- 查表层：建逆表直接查。
- 这些区段不依赖 RSA，可先行确定。

### 第 3 步：处理 RSA 覆盖区段
- 确认 RSA 参数（n、e）与覆盖范围。
- 若 e 小（如 3）且消息未填充：直接对密文开 e 次方根（整数开方）得明文。
- 若消息空间小：枚举候选 → 加密 → 比对。
- 若 RSA 只覆盖 16 字节且其它层已约束部分字节：用约束裁剪搜索空间。

### 第 4 步：拼接 + 一致性检查
- 把各段拼成完整输入。
- 检查区段重叠处是否同时满足多层约束。
- 验证所有层常量全部命中。

### 第 5 步：原程序验证
- 在原始未 patch 二进制上跑，确认通过全部校验。

## 三、验证清单

- [ ] 覆盖图完整，每个字节至少被一层约束。
- [ ] 每层常量都从二进制中直接提取并核对。
- [ ] RSA 区段的约束与其它层不冲突。
- [ ] 拼接后重叠字节同时满足所有覆盖它的层。
- [ ] 原程序验证通过。

## 四、常见坑

| 坑 | 表现 | 规避 |
|---|---|---|
| 以为 RSA 覆盖全部输入 | 试图对 44 字节整体逆 RSA | 先画覆盖图，确认 RSA 只管 16 字节 |
| 忽略区段重叠 | 拼接后某层校验失败 | 重叠字节列方程同时满足多层 |
| 大 e 当小 e 处理 | 开根失败 | 先确认 e 值，e≥65537 时改用枚举/约束求解 |
| 查表方向搞反 | 逆推结果错 | 明确是正查还是逆查，必要时建双向表 |
| 校验和字节序错 | 和值对不上 | 确认大小端、累加宽度（16/32 位） |
