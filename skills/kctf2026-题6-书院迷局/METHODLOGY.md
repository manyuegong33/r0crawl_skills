# 通用方法论：Android APK JNI 混合流程逆向（奇偶通道分离 + XOF/ARX + SAT + TEA/LCG）

> 适用题型：APK 内嵌 native 库，输入经 JNI 进入 so，按奇偶位/通道拆分成多路，每路独立的密码学变换（XOF 可扩展输出、ARX 状态机、TEA、LCG），最终归结为 SAT/SMT 求解或密钥恢复。典型特征：输入定长 hex（如 100 hex = 50 字节）、有自定义 section（如 .kctfguard）、多路独立验证。

## 一、题型识别特征

- APK 有 JNI 声明，输入长度固定（如 100 hex → 50 字节）。
- 输入按奇偶位/通道拆成两路（或多路），每路独立处理。
- so 中有自定义 section（如 .kctfguard）存放密钥材料。
- 出现 XOF（可扩展输出函数，如 SHAKE 类）、ARX（Add-Rotate-Xor）状态机。
- 存在稀疏布尔门约束（如 46 位）→ SAT 求解。
- 出现 TEA（delta=0x9e3779b9）或 LCG（如 1664525/1013904223）密钥流。
- 需要 GPU/CUDA 加速种子爆破（说明种子空间 2^32 量级）。

## 二、通用推导流程（6 步）

### 第 1 步：JNI 边界与数据流
- 用 jadx 看 Java 层入口，找到 native 方法签名。
- 用 IDA/Ghidra 打开 so，定位 JNI_OnLoad 与 RegisterNatives（动态注册时）。
- 跟踪输入从 Java 层到 native 层的拷贝点，确认长度校验。

### 第 2 步：通道拆分还原
- 找到奇偶位/通道拆分点（通常是位运算或字节交错）。
- 把输入拆成多路后，每路独立跟踪，避免交叉污染。

### 第 3 步：自定义 section 密钥恢复
- 检查 so 的 section 表，找非标准 section（如 .kctfguard）。
- 提取其中的密钥材料，确认是否在运行时被解密/异或。

### 第 4 步：XOF/ARX 状态机逆推
- XOF：确认 squeeze 长度与吸收顺序，逆推时按相同顺序 unsqueeze。
- ARX：每个 Add/Rotate/Xor 都可逆，按轮逆推；注意轮常量的来源（可能来自 LCG）。

### 第 5 步：SAT/SMT 求解稀疏布尔约束
- 把稀疏布尔门（如 46 位）翻译成 CNF 或 SMT-LIB。
- 用 z3/bitwuzla/cvc5 求解；若变量少可暴力。
- 得到的解作为某路的中间态。

### 第 6 步：TEA/LCG 密钥恢复 + 种子爆破
- TEA：确认 delta（0x9e3779b9）、轮数（通常 32）、密钥 128 位；逆推用解密轮。
- LCG：确认乘数/增量（如 1664525/1013904223），逆推用模逆元。
- 若种子空间 2^32：写 CUDA/OpenCL 内核并行爆破，或用彩虹表。

## 三、验证清单

- [ ] JNI 边界数据流完整，长度校验点明确。
- [ ] 通道拆分规则确认（奇偶/交错/字节序）。
- [ ] 自定义 section 密钥材料提取并验证。
- [ ] XOF/ARX 每步逆操作在单路样本上自洽。
- [ ] SAT 求解结果代入原约束通过。
- [ ] TEA/LCG 逆推后与已知中间态一致。
- [ ] 最终在模拟器/真机跑通。

## 四、常见坑

| 坑 | 表现 | 规避 |
|---|---|---|
| 动态注册 JNI 找不到函数 | 静态分析看不到 native 实现 |  hook RegisterNatives 或搜 JNI_OnLoad |
| 奇偶拆分方向错 | 两路数据都对不上 | 用已知输入差分确认拆分规则 |
| XOF squeeze 顺序错 | 逆推结果乱 | 严格按吸收顺序逆推 |
| ARX 轮常量来源漏掉 | 逆推到某轮断掉 | 确认轮常量是否来自 LCG/固定表 |
| SAT 变量编码错 | 求解器返回 unsat | 先用小规模已知样本验证编码 |
| 种子爆破用 CPU | 跑不完 2^32 | 上 CUDA/OpenCL 并行 |
