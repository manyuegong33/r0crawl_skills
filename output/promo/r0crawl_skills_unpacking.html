Android 脱壳：不是 Dump 一下，是把运行时代码带回分析台

识别保护 → 盯住加载 → 内存提取 → 修复重建 → Hash 与可用性校验
01 识别

壳特征、异常入口、ClassLoader、加固 SDK、匿名 RX

02 跟踪

attachBaseContext、dlopen、构造器、DEX/ELF 映射时机

03 Dump

DEX、OAT/VDEX、SO、匿名可执行内存与元数据

04 修复

header、map、section、重定位、导入、方法体与结构恢复

05 验证

SHA-256、manifest、反编译、重载、交叉引用与行为对照

它能把哪些模块串起来
入口识别：apk-protection-analysis + android-static-analysis
加载跟踪：apk-classloader-tracing + constructor-dlopen-tracing
内存提取：dex-memory-dump + memdumper-artifact-validation
重建校验：dump-fix-rebuild + dexfixer-reconstruction
为什么它比“给个脚本”更值钱
脚本只负责一次提取，流程负责判断何时提、提什么、怎么证明可用。
自动反编译只给线索，manifest、hash 和运行时证据才能形成交付。
遇到 anti-Frida、完整性校验、匿名 RX，还能继续路由到对应专项。
交付物不是一个孤零零的 dump.dex
evidence/raw/       原始 APK、运行日志、内存映射
evidence/derived/   DEX / SO / 修复产物
dump-manifest.json  地址、大小、来源、SHA-256
notes/timeline.md   加载与提取时间线
report.md           壳判断、证据、限制、下一步
